# Weather-station-Arduino
Create project with Arduino and JavaScript, Node.js, Mongo.db, Render, Postman
# 🌦️ Хмарна метеостанція на Arduino (Weather-station-Arduino)

Командний вебпроєкт для моніторингу погоди в режимі реального часу (температура, вологість, освітленість) та віддаленого керування платою Arduino через захищену панель на сайті.

---

## 🗺️ Як влаштована система (Архітектура)

```text
[Датчики: DHT11, Фоторезистор] ──► [Arduino + Node.js (USB)] ──► [Сервер на Render] ──► [MongoDB Atlas]
[Пристрої: LED, Екран LCD 1602] ◄── [Arduino + Node.js (USB)] ◄── [Сервер на Render] ◄── [Сайт (Браузер)]
```
*(Схема проєкту також збережена у файлі `architecture.png` у корені репозиторію).*

---

## 👥 Розподіл ролей у команді

| Учасник | Роль | Робоча гілка | Папка / Файли | Головний результат |
| :--- | :--- | :--- | :--- | :--- |
| **Учасник 1** | Hardware & Архітектор | `feature/hardware` | `hardware/` | Схема проєкту, збірка Arduino, відправлення даних із датчиків і прийом команд на LED/LCD |
| **Учасник 2** | Backend & Безпека | `feature/backend` | `backend/` | Хмарна БД MongoDB, сервер Express, шифрування паролів + JWT, зовнішній API погоди |
| **Учасник 3** | Frontend UI & Авторизація | `feature/frontend-ui` | `frontend/index.html`, `style.css`, `app.js` | Дизайн сайту, форми реєстрації/входу, захист панелі та живе оновлення цифр |

## 🤝 Єдиний формат даних (щоб код усіх 4 учасників зістикувався)

1. **Дані з датчиків** (Учасник 1 відправляє на сервер → Учасник 2 зберігає → Учасники 3 і 4 виводять на сайт):
   ```json
   {
     "temperature": 23.5,
     "humidity": 48,
     "light": 70
   }
   ```
2. **Команди керування пристроєм** (Учасник 4 відправляє з сайту → Учасник 2 зберігає → Учасник 1 виконує на Arduino):
   ```json
   {
     "led": true,
     "lcdText": "Hello World!",
     "interval": 15
   }
   ```

## 📋 Покрокові завдання для кожного учасника

🛠️ Учасник 1: Hardware & Архітектор
Твоя гілка: feature/hardware

Що потрібно від інших: публічне посилання на сайт від Учасника 4 (для кроку 4).

[ ] 1. Діаграма проєкту: завантажити фінальне зображення схеми architecture.png у корінь репозиторію.

[ ] 2. Збірка схеми на Arduino: підключити DHT11, фоторезистор, світлодіод та екран LCD 1602 I2C.

[ ] 3. Прошивка Arduino (.ino): написати скетч, який зчитує датчики, виводить температуру/вологість на 1-й рядок LCD 1602, відправляє JSON у Serial-порт і приймає команди із Serial для ввімкнення LED та виведення тексту на 2-й рядок екрана.

[ ] 4. Відправлення даних у хмару (hardware/hardware.js): написати скрипт на Node.js (serialport + axios), який кожні 15 секунд відправляє дані з USB на POST /api/weather (із захистом try/catch від обривів інтернету).

[ ] 5. Виконання команд із сайту через POST: реалізувати в hardware.js синхронізацію команд через POST-запити (axios.post()), кешування попереднього стану (lastCommands) і передачу змінених команд (LED:, LCD:, INT:) в Arduino через USB.

⚙️ Учасник 2: Backend, База даних, JWT та Зовнішній API
Твоя гілка: feature/backend

Що віддаєш команді: рядок підключення MONGODB_URI (після кроку 1) для Учасника 4.

[ ] 1. Хмарна БД (MongoDB Atlas): створити безкоштовний кластер M0, користувача БД, відкрити доступ 0.0.0.0/0 і скинути MONGODB_URI Учаснику 4.

[ ] 2. Сервер і моделі (backend/server.js): підняти Express + Mongoose і створити 3 схеми: Weather (дані датчиків), User (користувачі) та DeviceState (стан LED, текст LCD, інтервал).

[ ] 3. API датчиків і керування пристроєм через POST: написати маршрути POST /api/weather, GET /api/weather/current, GET /api/weather/history, а також POST /api/device/commands та POST /api/device/control для збереження й синхронізації команд керування.

[ ] 4. Безпека та JWT (bcryptjs + jsonwebtoken):

Реєстрація (POST /api/auth/register): зашифрувати пароль через bcrypt.hash() і обов'язково видалити поле password із відповіді сервера.

Логін (POST /api/auth/login): перевірити пароль і видати JWT-токен.

Захист: створити authMiddleware і закрити ним POST-маршрут керування пристроєм від неавторизованих користувачів.

[ ] 5. Зовнішній API погоди: отримати ключ на OpenWeatherMap і зробити маршрут GET /api/weather/external для отримання температури та вологості на вулиці.

🎨 Учасник 3: Frontend UI, Авторизація та Real-time
Твоя гілка: feature/frontend-ui

Що віддаєш команді: готовий index.html із порожніми блоками <div id="control-panel-slot"></div> та <canvas id="weatherChart"></canvas> для Учасника 4.

[ ] 1. Верстка головної сторінки (frontend/index.html): зробити шапку зі статусом станції («Онлайн / Офлайн»), картки показників з Arduino (температура, вологість, світло), блок «Погода на вулиці» та слоти під панель керування й графік.

[ ] 2. Форми реєстрації та логіну: зверстати форми реєстрації нового акаунта та входу.

[ ] 3. Стилізація та адаптивність (frontend/style.css): гарно оформити картки погоди, форми реєстрації/логіну та адаптувати сайт під екрани ПК.

[ ] 4. Оновлення температури в режимі реального часу (frontend/app.js): налаштувати опитування GET /api/weather/current і GET /api/weather/external через fetch() кожні 10 секунд без перезавантаження сторінки (якщо даних немає понад 1 хвилину — статус стає червоним «Офлайн»).

[ ] 5. Захист панелі керування на фронтенді: підключити форми до API, зберігати JWT-токен у localStorage і приховувати панель керування пристроєм від гостей, які не увійшли в акаунт.

☁️ Учасник 4: Хмара (Render), Панель керування та Графіки
Твоя гілка: feature/analytics-deploy

Що потрібно від інших: MONGODB_URI від Учасника 2 (для кроку 1) та слоти в index.html від Учасника 3 (для кроків 2 і 4).

Що віддаєш команді: робоче посилання на сайт https://...onrender.com (після кроку 1).

[ ] 1. Запуск сервера в хмарі (Render): зареєструватися на Render, прив'язати репозиторій, додати змінні MONGODB_URI, JWT_SECRET, WEATHER_API_KEY, запустити деплой і скинути робоче посилання команді.

[ ] 2. Панель керування пристроєм (frontend/control.js): вбудувати в #control-panel-slot перемикач світлодіода (Увімк. / Вимк.), поле введення тексту для екрана LCD 1602 (до 16 символів) та вибір інтервалу опитування (5с / 15с / 60с).

[ ] 3. Відправлення команд через POST із JWT-токеном: налаштувати відправлення команд із панелі POST-запитом (POST /api/device/commands або POST /api/device/control) із передачею токена з localStorage у заголовку Authorization: Bearer <token>.

[ ] 4. Графіки погоди (frontend/charts.js): підключити Chart.js до <canvas id="weatherChart"> і вивести графік температури та вологості за 1 годину / 24 години / 7 днів із GET /api/weather/history.

[ ] 5. Фінальна перевірка в хмарі: відкрити живий сайт на Render, зареєструватися, увійти, увімкнути світлодіод і відправити текст на екран LCD 1602.

   ```bash

   git commit -m "Опис того, що зробив"
   ```
