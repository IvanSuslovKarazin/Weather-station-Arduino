# Weather-station-Arduino
Create project with Arduino and JavaScript, Node.js, Mongo.db, Render, Postman
# 🌦️ Облачная метеостанция на Arduino (Weather-station-Arduino)

Командный веб-проект для мониторинга погоды в реальном времени (температура, влажность, освещённость) и удалённого управления платой Arduino через защищённую панель на сайте.

---

## 🗺️ Как устроена система (Архитектура)

```text
[Датчики: DHT11, Фоторезистор] ──► [Arduino + Node.js (USB)] ──► [Сервер на Render] ──► [MongoDB Atlas]
[Устройства: LED, Экран LCD 1602] ◄── [Arduino + Node.js (USB)] ◄── [Сервер на Render] ◄── [Сайт (Браузер)]
```
*(Схема проекта также сохранена в файле `architecture.png` в корне репозитория).*

---

## 👥 Распределение ролей в команде

| Участник | Роль | Рабочая ветка | Папка / Файлы | Главный результат |
| :--- | :--- | :--- | :--- | :--- |
| **Участник 1** | Hardware & Архитектор | `feature/hardware` | `hardware/` | Схема проекта, сборка Arduino, отправка данных с датчиков и приём команд на LED/LCD |
| **Участник 2** | Backend & Безопасность | `feature/backend` | `backend/` | Облачная БД MongoDB, сервер Express, шифрование паролей + JWT, внешний API погоды |
| **Участник 3** | Frontend UI & Авторизация | `feature/frontend-ui` | `frontend/index.html`, `style.css`, `app.js` | Дизайн сайта, формы регистрации/входа, защита панели и живое обновление цифр |
| **Участник 4** | Облако, Управление & Графики | `feature/analytics-deploy` | `frontend/control.js`, `charts.js`, Render | Запуск сайта в облаке (Render), панель управления LED/LCD и графики истории |

## 🤝 Единый формат данных (чтобы код всех 4 участников состыковался)

1. **Данные с датчиков** (Участник 1 отправляет на сервер → Участник 2 сохраняет → Участники 3 и 4 выводят на сайт):
   ```json
   {
     "temperature": 23.5,
     "humidity": 48,
     "light": 720
   }
   ```
2. **Команды управления устройством** (Участник 4 отправляет с сайта → Участник 2 сохраняет → Участник 1 выполняет на Arduino):
   ```json
   {
     "led": true,
     "lcdText": "Hello World!",
     "interval": 15
   }
   ```

## 📋 Пошаговые задачи для каждого участника

### 🛠️ Участник 1: Hardware & Архитектор
* **Твоя ветка:** `feature/hardware`
* **Что нужно от других:** публичная ссылка на сайт от Участника 4 (для шага 4).

- [ ] **1. Диаграмма проекта:** загрузить финальную картинку схемы `architecture.png` в корень репозитория.
- [ ] **2. Сборка схемы на Arduino:** подключить `DHT11` (пин `D2`), `фоторезистор` (`A0` + резистор 10 кОм), `светодиод` (`D8` + резистор 220 Ом) и экран `LCD 1602 I2C` (`SDA -> A4`, `SCL -> A5`).
- [ ] **3. Прошивка Arduino (`.ino`):** написать скетч, который читает датчики, выводит температуру/влажность на 1-ю строку LCD 1602, отправляет JSON в Serial-порт и принимает команды из Serial для включения LED и вывода текста на 2-ю строку экрана.
- [ ] **4. Отправка данных в облако (`hardware/hardware.js`):** написать скрипт на Node.js (`serialport` + `axios`), который каждые 15 секунд отправляет данные с USB на `POST /api/weather` (с защитой `try/catch` от обрывов интернета).
- [ ] **5. Выполнение команд с сайта:** добавить в `hardware.js` запрос `GET /api/device/commands` каждые 5 секунд и передачу команд в Arduino по USB.

---

### ⚙️ Участник 2: Backend, База данных, JWT и Внешний API
* **Твоя ветка:** `feature/backend`
* **Что отдаёшь команде:** строку подключения `MONGODB_URI` (после шага 1) для Участника 4.

- [ ] **1. Облачная БД (MongoDB Atlas):** создать бесплатный кластер `M0`, пользователя БД, открыть доступ `0.0.0.0/0` и скинуть `MONGODB_URI` Участнику 4.
- [ ] **2. Сервер и модели (`backend/server.js`):** поднять Express + Mongoose и создать 3 схемы: `Weather` (данные датчиков), `User` (пользователи) и `DeviceState` (состояние LED, текст LCD, интервал).
- [ ] **3. API датчиков и устройства:** написать маршруты `POST /api/weather`, `GET /api/weather/current`, `GET /api/weather/history`, а также `GET /api/device/commands` и `POST /api/device/control`.
- [ ] **4. Безопасность и JWT (`bcryptjs` + `jsonwebtoken`):**
  - Регистрация (`POST /api/auth/register`): зашифровать пароль через `bcrypt.hash()` и **обязательно удалить поле `password` из ответа сервера**.
  - Логин (`POST /api/auth/login`): проверить пароль и выдать `JWT`-токен.
  - Защита: создать `authMiddleware` и закрыть им маршрут `POST /api/device/control` от неавторизованных пользователей.
- [ ] **5. Внешний API погоды:** получить ключ на OpenWeatherMap и сделать маршрут `GET /api/weather/external` для получения температуры и влажности на улице.

---

### 🎨 Участник 3: Frontend UI, Авторизация и Real-time
* **Твоя ветка:** `feature/frontend-ui`
* **Что отдаёшь команде:** готовый `index.html` с пустыми блоками `<div id="control-panel-slot"></div>` и `<canvas id="weatherChart"></canvas>` для Участника 4.

- [ ] **1. Вёрстка главной страницы (`frontend/index.html`):** сделать шапку со статусом станции («Онлайн / Офлайн»), карточки показаний с Arduino (температура, влажность, свет), блок «Погода на улице» и слоты под панель управления и график.
- [ ] **2. Формы регистрации и логина:** сверстать формы регистрации нового аккаунта и входа.
- [ ] **3. Стилизация и адаптивность (`frontend/style.css`):** красиво оформить карточки погоды, формы регистрации/логина и адаптировать сайт под экраны ПК.
- [ ] **4. Обновление температуры в реальном времени (`frontend/app.js`):** настроить опрос `GET /api/weather/current` и `GET /api/weather/external` через `fetch()` каждые 10 секунд без перезагрузки страницы (если данных нет больше 1 минуты — статус становится красным «Офлайн»).
- [ ] **5. Защита панели управления на фронтенде:** подключить формы к API, сохранять `JWT`-токен в `localStorage` и скрывать панель управления устройством от гостей, которые не вошли в аккаунт.

---

### ☁️ Участник 4: Облако (Render), Панель управления и Графики
* **Твоя ветка:** `feature/analytics-deploy`
* **Что нужно от других:** `MONGODB_URI` от Участника 2 (для шага 1) и слоты в `index.html` от Участника 3 (для шагов 2 и 4).
* **Что отдаёшь команде:** рабочую ссылку на сайт `https://...onrender.com` (после шага 1).

- [ ] **1. Запуск сервера в облаке (Render):** зарегистрироваться на Render, привязать репозиторий, добавить переменные `MONGODB_URI`, `JWT_SECRET`, `WEATHER_API_KEY`, запустить деплой и скинуть рабочую ссылку команде.
- [ ] **2. Панель управления устройством (`frontend/control.js`):** встроить в `#control-panel-slot` переключатель светодиода (`Вкл / Выкл`), поле ввода текста для экрана LCD 1602 (до 16 символов) и выбор интервала опроса (`5с / 15с / 60с`).
- [ ] **3. Отправка команд с JWT-токеном:** настроить отправку команд из панели на `POST /api/device/control` с передачей токена из `localStorage` в заголовке `Authorization: Bearer <token>`.
- [ ] **4. Графики погоды (`frontend/charts.js`):** подключить `Chart.js` к `<canvas id="weatherChart">` и вывести график температуры и влажности за `1 час / 24 часа / 7 дней` из `GET /api/weather/history`.
- [ ] **5. Финальная проверка в облаке:** открыть живой сайт на Render, зарегистрироваться, войти, включить светодиод и отправить текст на экран LCD 1602.

## 🚀 Как начать работу в Git (шпаргалка для каждого)

1. **Скачать проект на компьютер (выполняется 1 раз):**
   ```bash
   git clone [https://github.com/ВАШ-ЛОГИН/Weather-station-Arduino.git](https://github.com/ВАШ-ЛОГИН/Weather-station-Arduino.git)
   cd Weather-station-Arduino
   ```
2. **Переключиться в СВОЮ ветку (не писать код в `main`!):**
   ```bash
   git checkout имя-твоей-ветки
   ```
3. **Сохранить и отправить готовую работу на GitHub:**
   ```bash
   git add .
   git commit -m "Описание того, что сделал"
   git push origin имя-твоей-ветки
   ```
4. **Завершить задачу:** зайти на GitHub, нажать зелёную кнопку **Compare & pull request** и объединить свою ветку с `main`.
